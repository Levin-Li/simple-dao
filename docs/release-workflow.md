# 发布流程

**每次发布必须先执行 `clean`，不允许单独执行 `deploy`。** 使用 `clean deploy` 时，Maven 先清理所选模块，再构建、测试并发布。

## 发布前检查

1. 核对目标分支、当前版本及本次变更文件，确定被修改的 Maven 模块。
2. 运行相关模块测试和项目要求的示例兼容性测试，全部通过后提交代码。
3. 不自动修改版本号、POM 或 Git 标签；版本管理由用户明确决定。

## 默认发布：仅清理并发布改动模块

从项目根目录执行 `clean deploy`，通过 `-pl` 明确选择被修改的模块，不默认添加 `-am` 或清理整个项目。

例如本次改动涉及 JPA 模块和示例模块：

```bash
mvn -pl simple-dao-jpa,simple-dao-examples clean deploy -P '!01-跳过测试'
```

使用目标分支适配的 JDK。发布时不跳过测试；未修改的模块使用已有依赖。

## 发布失败：清理并发布整个项目

若上述改动模块的发布命令返回非零退出码，先记录失败原因，再从项目根目录执行全项目发布：

```bash
mvn clean deploy -P '!01-跳过测试'
```

只有发布失败后才进入这个回退步骤。如果全项目发布仍失败，修复实际错误并重新执行，不得报告发布成功。

## 发布后确认

- 确认 Maven 发布命令成功结束，并核对测试报告。
- 按用户授权推送到目标远端分支，核对远端提交和本地提交一致。
- 报告发布版本、分支、提交号及实际采用的发布范围。
