# 代码生成模块真实集成测试流程

本流程验证的是 `simple-dao-code-gen` 实际生成的源码与实际 Spring 缓存代理行为，不能只以 Freemarker 渲染文本或 JavaParser 语法解析替代。

## 1. 清理仓库

在仓库根目录执行：

```bash
mvn clean
```

## 2. 生成 example 项目模板

进入 `simple-dao-code-gen-example` 根目录：

```bash
cd simple-dao-code-gen-example
mvn simple-dao-codegen:gen-demo-project-template
```

此步骤生成 `entities` 模块及项目根 POM 的模块定义。

## 3. 编译实体并生成服务

```bash
cd entities
mvn compile
mvn simple-dao-codegen:gen-code
```

检查生成结果：

```bash
rg -n "handleUniqueCacheEvict|uniqueCacheRelationListener|findBy" \
  ../services-impl/src/main/java ../services/src/main/java
```

带单字段和组合唯一约束的实体必须生成相应 `findBy...` 方法、`UK:` 唯一查询缓存 key 与 `UKI:` 主键反向关联索引处理。

## 4. 编译真实生成服务

回到 example 根目录：

```bash
mvn -pl services,services-impl -am compile
```

这是生成类编译门禁，JavaParser 成功不能替代它。

## 5. 验证真实 Spring 缓存行为

使用编译后的 `*ServiceImpl` 启动最小 `AnnotationConfigApplicationContext`，注册：

- `@EnableCaching(proxyTargetClass = true)`；
- `ConcurrentMapCacheManager`，缓存名为生成 Service 的 `CACHE_NAME`；
- 生成的 `ModuleSpringCacheResolver`，Bean 名为 `ModuleOption.PLUGIN_PREFIX + "ModuleSpringCacheResolver"`；
- 与生成参数一致的 `spelUtils` Bean；
- 计数型 `SimpleDao` 替身，返回带主键 ID 的生成 `Info`。

必须断言：

1. 首次唯一查询使 DAO 加载次数为 `1`；
2. 相同参数第二次查询仍为 `1`，证明真实 `@Cacheable` 命中；
3. 调用 `clearCacheByKeySuffix(id)`；
4. 相同参数第三次查询加载次数为 `2`，证明主键驱逐已清理关联 `UK:` 缓存；
5. `UKI:<id>` 索引与该 ID 的关联唯一 key 被删除，其他 ID 的缓存不受影响。

## 6. 回归测试

```bash
mvn -pl simple-dao-code-gen test
mvn -pl simple-dao-examples -am \
  -Dtest=DaoExamplesTest,DaoJsonExamplesTest,DaoQueryExamplesTest \
  -Dsurefire.failIfNoSpecifiedTests=false test -P '!01-跳过测试'
```

## 验收标准

- 项目模板、实体编译、`gen-code` 和生成服务编译都成功；
- 真实生成类的唯一缓存命中与 ID 关联驱逐行为通过；
- 代码生成模块测试与示例兼容性测试通过。
