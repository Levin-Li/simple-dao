## Context

默认服务把 `findById`、列表及通用键缓存放在实体的默认 `CACHE_NAME` 中。缓存注解仅按主键驱逐；`handleEvent` 已经以 `<实体类全限定名>/<动作>` 主题发送 `DaoEventBus` 事件，但当前没有默认消费者，且发送发生在事务提交前。实体局部更新仍可能使任何唯一查找返回的完整 Info 对象过期。

## Goals / Non-Goals

**Goals:**

- 从实体唯一约束生成单字段及组合字段的唯一查找方法和独立缓存分组。
- 保留缓存注解对主键缓存的既有职责。
- 在实体变更成功提交后，通过现有 `DaoEventBus` 统一清空全部唯一查询缓存分组。
- 允许实现类以静态方法调整每个唯一字段组合的缓存开关，标准服务接口只读查询开关状态。

**Non-Goals:**

- 不解析局部更新请求来执行精确单键失效。
- 不为原生 SQL、跨进程或数据库脚本自动发现实体变更；这些入口必须在提交后发布既有事件主题，跨节点需替换默认本地事件总线。
- 不改变主键缓存键、列表缓存逻辑或增加第三方依赖。

## Decisions

### 以独立 cacheName 表示唯一缓存分组

每个唯一字段组合生成稳定的 `CACHE_NAME + ":uk:" + <组合名称>`。事件消费者对每个组调用 `moduleCacheService.clear(cacheName)`。选择独立缓存名而非默认缓存下的前缀删除，因为现有 `CacheService` 仅支持单键驱逐或整个 cacheName 清空。

### 所有实体变更清空全部唯一缓存组

唯一查找缓存保存完整 Info 对象。即使局部更新未修改唯一字段，缓存中的其他字段仍可能过期。因此单条和批量创建、更新、删除成功后均清空该实体所有唯一缓存组。拒绝按请求字段或旧值精确驱逐，因为它无法覆盖条件更新和外部事件，且增加不必要的读取与复杂性。

### 使用现有 DaoEventBus，并延迟到 afterCommit 分发

缓存注解继续处理 ID 缓存。`handleEvent` 在存在同步事务时注册 afterCommit 回调，提交后再发送事件；无事务时立即发送。默认服务在初始化阶段订阅自身实体主题并清空唯一组。这样默认 Service 与外部写入共享相同的失效入口。

### 唯一开关的键是完整属性组合

实现类使用静态、线程安全的状态表，以字段声明顺序连接的组合名为键。标准接口的 `isUniqueFindCacheEnabled(String...)` 仅在参数精确匹配一个生成的唯一组合时返回其状态。静态设置方法只在实现类提供。开关变化时递增该组版本；缓存 key 含版本，以防关闭后重新开启时复用旧条目。

## Risks / Trade-offs

- [任何写入均清空全部唯一组会降低命中率] → 仅影响有唯一查询缓存的实体，换取局部更新和条件更新下的正确性。
- [默认 DaoEventBus 仅限 JVM 内] → 文档化事件主题；分布式部署由应用提供兼容的 DaoEventBus 实现。
- [静态开关不跨 JVM 同步] → 将其限定为当前 JVM 的实现类运行时策略；跨节点统一策略应在各节点执行同一设置或由应用配置驱动。
- [组合唯一约束可能含可空字段] → 生成的方法沿用 `findUnique` 语义，并以参数非空条件决定是否进入缓存。
