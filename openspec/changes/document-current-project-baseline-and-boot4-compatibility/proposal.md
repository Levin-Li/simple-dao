## Why

当前仓库已经形成了可运行、可发布的多模块能力集合，但 `openspec/` 目录仍然只有基础配置，没有把项目现状、产品边界和本轮 Spring Boot 4 兼容升级沉淀为正式需求文档。

这会带来三个问题：

- 后续需求和改动缺少统一的基线参照，容易把运行时能力、代码生成能力和示例工程混写在一起。
- 本轮 Spring Boot 4 兼容、依赖收敛、自动配置注册调整与发布约束没有被显式记录。
- 后续再做需求变更时，无法基于 OpenSpec 判断“当前支持什么”和“新增修改了什么”。

## What Changes

- 新建当前态运行时规格 `simple-dao-runtime`，描述注解驱动查询、统一 DAO、JPA 自动配置、基础领域模型和 UID 生成能力。
- 新建当前态代码生成规格 `simple-dao-codegen`，描述模板生成、数据库元数据读取、服务代码生成和生成参数约束。
- 新建本次 change 的 `proposal.md`、`design.md`、`tasks.md`，说明为什么要把仓库需求补齐到 OpenSpec，以及采用何种拆分方式。
- 在当前规格中显式纳入 Spring Boot 4 兼容和发布基线要求，使后续演进可以沿着现有规格继续修改。

## Impact

- 影响范围仅限 `openspec/` 文档，不修改运行时代码或生成器实现。
- 后续功能需求、兼容性升级或生成器演进应优先落在 `simple-dao-runtime` 或 `simple-dao-codegen` 对应规格中。
- 本轮文档补齐完成后，OpenSpec 将同时具备“当前支持什么”与“为什么按这个边界建模”的上下文。
