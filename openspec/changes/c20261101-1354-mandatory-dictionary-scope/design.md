## Context

`MandatoryCondition.ofBranches` 当前复制并拒绝非 `Enum<?>` 值；`ConditionBuilderImpl` 仅允许枚举字段生成 IN，`JpaDaoImpl` 创建前也仅验证枚举字段。Simple DAO 不负责字典候选加载，必须继续与 Servlet、RBAC 和租户数据解耦。

## Goals / Non-Goals

**Goals:**

- 接受非空不可变 String 与 Integer/Long 标量值，仍按字段类型校验并参数绑定。
- 对支持的 JSON 字符串列表字段，全部已存成员均须属于同一分支允许集合；任何未授权成员拒绝整条记录。
- 完整复用原 DNF、作用域变化拒绝、更新前后范围和直接 JPA 写入边界。
- 测试真实 H2/JPA 的查询、COUNT、更新、删除、创建与枚举回归。

**Non-Goals:**

- 不允许客户端直接输入任意 SQL、字段路径或动态 JSON Path。
- 不把 `List<String>` JSON 属性解释为标量，不用“任一允许值”或读后过滤代替“全部成员允许”。
- 不读取字典表、判断字典项状态或改变普通业务安全模式。

## Decisions

1. 扩展原 `ofBranches` 的值白名单，只接受 Enum、String、Integer、Long；同一属性的值必须同一 Java 类型，空集合继续形成拒绝，输入深拷贝且不随调用方修改。
2. 渲染前核对实体真实直达属性类型。Enum 值保持 JPA/native 原转换；String/Integer/Long 只允许与实体标量字段精确匹配或安全的基础类型装箱匹配，均通过占位符绑定。任意 List/数组/JSON 对象及不匹配类型失败关闭。
3. `and` 保留同字段交集与分支笛卡尔语义；枚举和字典标量不得因字符串显示相同而混用。
4. 创建入口按实体字段值核对每一分支。直接 UPDATE/DELETE/SAVE 等原有拒绝策略保持；更新中的后置范围与旧范围均检查。
5. 用户确认新增项目中立的显式字段标记，只有该标记且实体字段类型为 `List<String>` 的 JSON 数组才能使用全部成员范围；不从普通 `List<String>` 或 Hibernate 注解自动推断。使用 Hibernate JSON 函数构造“非空且不存在任何不属于允许集合的数组元素”的谓词。JSON 路径只由固定 `$[*]` 和安全生成的变量名组成，所有字典值通过参数绑定；非数组、非字符串元素和不支持该函数的方言失败关闭。创建值检查要求列表非空且全部成员在允许集合，更新后的列表仍需满足相同限制。

## Risks / Trade-offs

- 多数据库方言绑定差异：标量使用现有 IN；JSON 列表只对真实执行验证过的方言承诺，未知方言失败关闭。
- 上游传入未经验证的字典码：本层只保证字段和值类型及参数绑定，上游必须核对字典 key、启用状态、租户和选项值。
- 旧枚举行为回归：必须运行 core 聚焦测试与三个 Examples 契约测试。

## Migration Plan

无需数据库迁移。更新依赖构件后，只有安装受信提供器且显式返回标量范围的实体会受到新能力影响；旧枚举范围与无提供器实体保持原语义。
